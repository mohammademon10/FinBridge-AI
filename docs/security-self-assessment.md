# FinBridge AI — Security Self-Assessment Report

**Application:** FinBridge AI  
**Assessment Target:** Full MVP Prototype (Frontend + Backend + AI Gateway)  
**Track:** 2026 Shenzhen International FinTech Competition (FinTechathon), International Track  
**Evaluator:** FinBridge AI Engineering Team  
**Status:** Approved for Sandbox & Demo Evaluation  
**Date:** October 2026  

---

## 1. Security Design Principles

1. **Defense in Depth:** Validation occurs at the client UI, at the FastAPI gateway (Pydantic schemas), and within core decimal service modules.
2. **Principle of Least Privilege:** The application does not request, require, or store any sensitive banking credentials, API keys, or personally identifiable information (PII).
3. **Deterministic Separation of AI from Math:** The LLM agent has no arithmetic authority and cannot alter backend financial states directly.

---

## 2. Threat Modeling & Risk Mitigation

| Threat Vector | Risk Level | Mitigation Strategy | Verification Status |
|---|---|---|---|
| **AI Hallucination of Financial Figures** | High | LLM is forbidden from computing numbers. All values are generated by deterministic backend functions using Python `Decimal` (`ROUND_HALF_UP`). | Verified via unit tests (`test_agent.py`) |
| **Real Money Transfer Exploitation** | Critical | The application contains no money-moving code or payment gateways. An interceptor in the AI agent rejects any transaction requests. | Verified via test case (`test_agent_chat_transfer_safety_guardrail`) |
| **SQL Injection** | High | SQLite interactions use parameterized queries (`?` placeholders). No dynamic string interpolation is permitted. | Verified in `app/db/database.py` |
| **Exposure of Secrets & Keys** | High | Strict `.gitignore` excludes `.env`, private keys, and credential stores. Repository contains only `.env.example`. | Verified via Git history audit |
| **Information Leakage via Errors** | Medium | Custom exception handlers catch unhandled errors and return sanitized generic error messages (`INTERNAL_ERROR`). No stack traces returned to clients. | Verified in `app/main.py` |
| **Floating-Point Rounding Exploits** | Medium | All monetary operations use standard Python `Decimal` rather than IEEE 754 floating-point primitives. | Verified via unit tests (`test_budget.py`) |
| **Cross-Origin Resource Sharing (CORS)** | Medium | FastAPI CORS middleware specifies allowed origins explicitly rather than using wildcard `*` with credentials. | Verified in `app/main.py` |

## 3. Data Privacy & Minimization

- **No Passport or Identity Document Storage:** Unlike real banking onboarding, the prototype explicitly operates without collecting passport scans, government IDs, or student identity cards.
- **Demo Scenarios:** All pre-loaded scenarios represent generalized benchmark university student profiles (e.g. TU Munich, Imperial College, Univ of Toronto) with no linkage to living individuals.
- **Client-Side Minimization:** Scenario data is ephemeral unless the user explicitly clicks the "Save Scenario" button to store a non-sensitive planning profile.

## 4. OWASP API Security Top 10 Checklist

1. **API1: Broken Object Level Authorization:** Passed — No user tenancy isolation required for public planning scenarios; scenario IDs use random UUIDs.
2. **API2: Broken Authentication:** Passed — Prototype is non-authenticated by design to eliminate credential theft risks.
3. **API3: Broken Object Property Level Authorization:** Passed — Strict Pydantic models validate and filter unexpected request fields.
4. **API4: Unrestricted Resource Consumption:** Passed — Inputs have bounded lengths (e.g. string lengths $\le 2000$, months $\le 120$).
5. **API5: Broken Function Level Authorization:** Passed — Allowlisted tool execution dispatcher validates tool names against a hardcoded list.
6. **API6: Unrestricted Access to Sensitive Business Flows:** Passed — No payments or financial executions exist.
7. **API7: Server Side Request Forgery (SSRF):** Passed — No dynamic external URL fetches are performed based on user input.
8. **API8: Security Misconfiguration:** Passed — Debug mode is disabled; CORS is configured with specific origins.
9. **API9: Improper Inventory Management:** Passed — Interactive Swagger documentation is automatically generated from typed schemas at `/docs`.
10. **API10: Unsafe Consumption of APIs:** Passed — Exchange rate fallbacks and agent tools handle timeouts and invalid responses safely.

## 5. Security Self-Assessment Conclusion

FinBridge AI adheres strictly to the security guardrails set forth in `rules.md` and the competition brief. The prototype presents **zero risk of unauthorized financial transactions** and **zero risk of personal credential leakage**, making it secure and suitable for evaluation by competition reviewers.
